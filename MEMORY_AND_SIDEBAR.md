# Local memory and responsive sidebar — 2.15.0

SARU's existing private `%APPDATA%/SARU_AI/memory.db` now includes a searchable journal. Original `messages` and `notes` tables remain intact. Existing conversations, notes and complete task-log lines are imported incrementally, with stable source IDs to avoid duplicate imports. Conversation and actual local result events are saved as they happen when remembering is enabled. Office job state/result/review and exported file paths are refreshed from the existing local Office database during synchronization. Office snapshots update the same record; this is not an audit of every OS action or every intermediate Office revision. Old conversations had no timestamp: their imported date is explicitly marked unknown rather than invented.

Open **Settings → Memory → View notes**, **Apps & Tools → Saved memory**, or the Office preview's Memory control. Search by topic, filter conversations/notes/tasks/Office/files, refresh the page, add an explicit note or export the journal to an owner-chosen text file. The UI shows at most 100 matching records at a time; exporting includes every journal record. Raw microphone audio, screen/camera recordings, browser passwords and API keys are not journal inputs. Credential-like text and exact configured API keys are withheld on journal writes and reads. This is best-effort text filtering, not a guarantee that arbitrary unlabeled secrets can be recognized. Private databases, logs and exports must never be published to GitHub.

`recall <topic>` searches across the journal. Ordinary provider text requests receive a bounded topical memory selection. Gemini Live can call the read-only `recall_local_memory` tool for a current SARU-addressed spoken request or explicit text request, without restarting the voice session. Each lookup uses a separate, properly closed SQLite connection and a bounded response. The model may choose whether to request a lookup; it cannot see every saved record simultaneously or promise perfect recall. Tool results are data, never authority to run actions. Unaddressed background speech and arbitrary function names cannot read memory or execute tools through this interface.

Turning off **Keep text and completed voice conversations in local memory** stops new automatic journal entries and automatic lookup. Existing journal data is preserved; explicit owner-created notes can still be saved. Legacy task logs retain their existing behavior outside the journal. Optional Office/log read errors are displayed as incomplete synchronization rather than preventing access to existing memory.

The sidebar now spans the available height below the header, independently of the bottom chat area. Settings and owner profile stay at the bottom. Button heights follow the actual viewport and font metrics; when minimum readable buttons cannot all fit, the local scrollbar and wheel remain available, including over SARU Office and Device & AI controls. High-resolution wheel deltas accumulate correctly. All existing themes, commands and the bottom chat layout are retained.

Validation: 54 focused memory/voice/settings/lifecycle/native-widget tests, plus the full isolated application GUI smoke test covering search/filter, actual task-result recording, large-window fit and small-window scrolling. Synthetic data only; these checks do not require microphone recording or owner-account messages. Live function-response handling follows the official Gemini Live tool interface: https://ai.google.dev/gemini-api/docs/live-api/tools
