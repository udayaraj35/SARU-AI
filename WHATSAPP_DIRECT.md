# Direct owner-requested WhatsApp sending — 2.20.3

Settings → Tools → **Send exact WhatsApp owner requests without a second Send confirmation** enables the owner's requested workflow. It is off by default for other installations; the owner explicitly requested it on their local installation.

An explicit request such as `WhatsApp ma Test Contact lai: Hello` or `open WhatsApp and send a message to Test Contact: Hello` supplies the channel, recipient and message. SARU resolves one exact visible contact (or the supplied phone number), prepares the draft, checks that it matches the request, and submits it once. A second "send" or "OK" is not required in this mode. The existing commit path rechecks recipient header, draft, URL, files and enabled submit control. A click is reported as submitted, not verified delivery. Ambiguous/missing contacts, changed drafts and login failures do not trigger a guessed click or automatic retry.

Only the natural owner-request route uses this preference. Raw social JSON and other platforms retain review. Disabling the setting restores draft review. Unsolicited incoming messages do not authorize replies. Voice activation is not reliable speaker authentication; enabled direct sending therefore applies to whatever completed request passes the existing wake/conversation gate.

This integration uses SARU's separate visible Playwright social session. The user must complete its QR login locally; the logged-in native Windows WhatsApp or embedded Qt browser is not the same session. Manual computer-use tests in the native app do not establish that SARU's voice/browser integration has been tested with a real account.

SARU's own registered callbacks are also accessible with `SARU ma Owner Profile kholnu`, `SARU ko API Manager khola`, `open option Home`, `open option Apps & Tools`, `open option Device Control`, `open option Weather`, `list app options`, `list buttons`, `press button <exact label>` and existing Settings field/tab controls. Missing or ambiguous labels report an error instead of guessing coordinates. API/security fields and source changes retain their protected workflows; this is not unrestricted self-modification.

Validation includes exact one-shot preparation/commit, default review, raw-JSON review preservation, changed-recipient refusal and UI routing with synthetic contacts. No new real contact messages are sent as part of this release test.

SARU Browser compatibility: the installed Qt package was already current, but its default HTTP browser string included an extra QtWebEngine token. The embedded profile now uses a compatible string while reporting its actual bundled Chromium version, not a fabricated newer Chrome version. In an isolated native Qt browser, WhatsApp Web exposed the scan-to-login/phone-link controls instead of the Chrome-update block. The bare address `whatsapp` also resolves to the real WhatsApp Web URL. No Windows/Chrome installation is changed. The existing browser must close/reopen after the source update to use the new profile configuration; cookies/profile paths are preserved. This embedded Qt profile remains separate from the Playwright automation profile.
